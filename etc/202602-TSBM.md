### 1. 에이전트

- 문의나 신고가 사람이 하기에는 너무 많다. 일 문의 3000, 신고 100000
  - ASIS: Rule-based System + 사람
    - 인력, 비용,일관성 문제도 있음
  - TO-BE: Agentic System
    - 1단계: LLM 챗봇: 1. 운영자를 돕는 2. 답변은 잘하지만 실제 권한은 없는 3. 결국 사람이 처리해야 함
    - 2단계: N8N workflow: 1. 정해진 분기를 따라감 2. 새로운 케이스마다 분기 추가 3. 현실의 복잡한 판단을 커버 못함
    - 3단계: Agentic System: 1. 목표를 주면 스스로 판단, 도구도 선택하고 실행. (자율성)
      - 정책 읽기 -> 맥락 이해 -> 판단 -> 실행
      - 핵심은 '목표를 주면 스스로 계획하고 실행한다'
        - => 위험성 관리는? 하네스 어떻게 만들었을라나

### 2. 도구 & 멀티에이전트

- 도구: 에이전트의 손발
  - 도구를 통해 현실세계의 데이터를 조회하고 처리할 수 있음
  - 어떤 도구를 쓸지 에이전트가 스스로 판단하게 함
  - 예시
    - 콘텐츠 조회: 처리 대상 내용 읽기
    - 정책 조회: 판단 기준 가져오기
    - 처리 API 호출: 실제 액션 실행
    - 알림 생성: 사용자에게 안내
      - => 질문: 오인차단이나 오동작에 대한 트러블슈팅 경험
  - 도구에 대한 설명의 중요성: Skills 같은 느낌인가?
    - Description을 명확하게 작성
      - 언제? 어떻게? 써야하는지.
        - 결론은 육하원칙이네.
      - 파라미터 스키마 정확하게
        - 타입, 필수 여부, 허용값 등
        - 필요시 값을 고정하는것도 방법이 될 수 있음.
- 그런데, 에이전트 하나로 다하면 한계가 있음. **멀티 에이전트**가 필요함.
  - 컨텍스트 과부하: 성능 저하
  - 역할 경계 모호: 예측 불가 동작
  - 오류 추적 어려움: 어디서 틀렸는지 모름
- 결국 에이전트 팀 구성이 필요함.
  - 분류
    - 콘텐츠 조회
    - 처리 항목 선택
  - 검토
    - 정책 조회
    - 수락/거부 판단
    - (주관 배제)
  - 검증
    - 체크리스트 실행
    - 오판단 발견시 재검토
  - 처리
    - 우선순위 선택
    - 알림 생성
    - API 호출
- 협업 과정
  - 분류 -> 검토 -> 검증 -> 처리
    - 검증 -> 검토로 피드백 루프 형성

### 3. 지식 관리 & 최적화

- 지식 관리는 프롬프트 밖에서
  - 기술적 이유
    - 컨택스트 비대
    - lost in the middle
    - 성능저하
    - 토큰 비용
    - 정책 변경시 프롬프트 수정
  - 조직적 이유
    - 비엔지니어도 에이전트를 개선 할 수 있어야 함.
    - 정책 담당자: 문서만 수정 -> 에이전트 판단 변경
    - 프롬프트 = 엔지니어 / 정책 = 담당자
      - 오너십 분리로 개선싸이클 가속
- RAG = 꼭 벡터 검색이어야 할까
  - 생각보다 의미 기반 검색 잘 안함.
    - => 애초에 데이터 소스 관리를 '우리가' 할 수 있으면 벡터검색 굳이? 우리가 대분류 하면 됨. 벡터가 답이 아님 - 애초에 모델 바뀌면 못써먹음
  - 에이전트가 지식 개선에도 참여 할 수 있음
    - 잘못된 지식이 잘못된 동작의 원인이 되는 경우가 많음
    - 사람이 인지하기 쉽지 않음
    - 에이전트에게 **로깅 도구를 제공**하고 모호한 내용 / 모순된 내용이 있으면 직접 피드백 기록
    - 담당자 확인 -> 정책 보완 -> 에이전트 재판단
- 모델 선택: 모두 같은 모델?
  - 에이전트마다 요구사항 다름
  - 반복판단 vs 정밀 검증은 다름
  - 비용/성능/레이턴시 고려 필요
  - 비용/성능/레이턴시 트레이드오프 -> 역할별 모델 분리 필요
    - 레이턴시 생각보다 중요함..
  - 결국은 써보는게 좋음
    - 단순 분류/처리/도구실행
      - Flash, Haiku, mini
    - 정책 판단/논리적 근거
      - Pro, Opus, O3...
